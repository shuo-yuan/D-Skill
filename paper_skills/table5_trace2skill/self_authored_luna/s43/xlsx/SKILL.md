## Core Workflow

1. Inspect the workbook and completed examples before editing. Enumerate actual sheet names and positions, dimensions, headers, populated bounds, formulas, merged ranges, structural rows, source and destination layouts, stable identifiers, lookup sources, and the exact required output path; do not assume the active sheet or prompt-described layout.
2. Define the authoritative source, exact target cells and ranges, data-row boundaries, ordering, matching semantics, grouping rules, and all required criteria before writing. Protect headers, totals, separators, unrelated sheets, existing correct output, and cells outside the requested scope.
3. Read source rows into stable snapshots and transform in memory. Use complete composite keys, authoritative ID order, row-level mappings, and explicit fallback behavior; do not reprocess generated rows or infer relationships from positional offsets.
4. Apply the smallest justified change. Preserve source order and aligned fields; use value-only edits when structure and styles must remain unchanged, and copy required styles and dimensions when relocating, expanding, compacting, or matching a reference layout.
5. Batch requested value, formula, formatting, and sheet changes, save directly to the exact requested filename and directory, recalculate when needed, then reopen or read back the saved workbook and verify the complete relevant result.

## Inspection

- Inspect every relevant sheet, including worksheet order, exact names and capitalization, dimensions, headers, first data row, populated coordinates, blank and repeated-header separators, summaries, totals, month headers, criteria lists, lookup tables, marker columns, and destination bounds. Locate columns by exact headers and recalculate indices after structural edits.
- Scan the full specified range and all independent or repeated blocks; identify actual final populated rows, intentional leading or trailing blanks, merged cells, section boundaries, and metadata rows. Treat `None`, empty strings, whitespace-only values, and formatted blanks appropriately; headers are not records, and formatting alone is not content.
- Confirm source and target sheets, columns, ranges, row mappings, reference layouts, and whether the task requires exact-value, case-insensitive, substring, containment, prefix, suffix, or first/last-match behavior. For normalized text, use type-safe `str(value).casefold()` only where requested; for exact suffixes compare the rightmost `LEN(reference)` characters.
- For synchronization and duplicates, identify every field in the identity key, count full-key occurrences, map existing rows by unique ID, preserve authoritative order, and prepare placeholders for missing IDs. Inspect all disambiguating fields for repeated labels, including category, item, year, period, rank, or column header.
- Normalize native dates, datetimes, recognized date strings, numeric cells, and numeric-text cells into comparable typed keys. Distinguish exact dates from latest-at-or-before lookups, derive relative cutoffs from the maximum valid date when required, and read designated start/end criteria; use inclusive ranges or an exclusive next-month boundary as specified.
- Inspect source rows and completed examples before expansion, insertion, sorting, or label generation. Record original row numbers, styles, dimensions, group transitions, first-appearance positions, and count values; determine whether a transformation is row-level or cumulative rather than inferring it from labels.
- For comments or text extraction, search complete text, normalize parameters as required, require every criterion, and combine filters before emitting output. For formatting-based extraction, require both the requested style condition and a nonblank value.
- For subset totals, enumerate all candidate combinations within the requested tolerance. For marker formulas or trimming, locate actual markers, track previous markers, and define intervals as `previous_marker + 1` through `current_marker - 1`; adjacent markers represent empty intervals.

## Writing Output

- Clear and repopulate the complete requested destination region when replacing results so stale rows and cells cannot remain, while preserving required headers, totals, unrelated content, and designated structural rows. Pack qualifying records consecutively and advance the destination only after all filters pass.
- For authoritative-ID synchronization, emit rows in source ID order, retain complete existing rows, and use `[ID] + [None] * remaining_columns` for missing IDs. For enrichment, build an in-memory key-to-attributes map. For wide-to-long output, retain identifying columns on every row and emit variables in the required header order.
- Use explicit composite keys and mappings with unchanged fallbacks such as `mapping.get(value, value)`. Emit every matching duplicate in source order when requested; do not copy a group summary across distinct row-level records. Keep paired fields aligned and preserve first-seen group order unless another order is specified.
- Snapshot original rows before expansion, insertion, sorting, or rearrangement. Emit copies consecutively from original rows only, use one copy for missing or invalid counts and at least one for valid counts, insert multiple targets bottom-to-top, delete rows bottom-to-top, and preserve section headers, separators, neighboring heights, hidden state, and styles.
- Copy values, formulas, styles, number formats, alignment, fonts, fills, borders, protection, widths, heights, and relevant dimensions when transferring or relocating data. For value-only edits, assign only requested values. When changing only a font or number format, preserve all other presentation attributes.
- Generate formulas systematically across the actual populated extent. Use `SUMIF` for one condition, `SUMIFS` with one range per condition, `SUMPRODUCT(ISNUMBER(MATCH(...))*sum_range)` for list membership, and `INDEX/MATCH` with absolute lookup ranges, relative input references, and `IFERROR` for copyable lookups. Anchor shared ranges, fixed selectors, and cumulative starts such as `$A$2:A{r}`; leave only intended row or period references relative.
- Use inclusive month starts and exclusive next-month bounds such as `date_range>=month_header` and `date_range<EDATE(month_header,1)`. Guard optional inputs with nonblank tests, avoid circular target references, write `=0` for empty marker intervals when required, and place endpoint summaries only in their designated cells.
- Preserve the priority order of mutually exclusive conditions and put fallbacks last. For tied maximum allocation use `IF(value=MAX(range),total_points/COUNTIF(range,MAX(range)),0)`. For grouped descending ranks count greater values and prior equal values only within the group, leaving incomplete rows blank. For signed scaling use `5*x/max_positive` for nonnegative values and `5*x/ABS(min_negative)` for negative values.
- For sequential labels, read original values first, track numeric bases and blank counts separately, generate Excel-style suffixes with repeated `divmod(n - 1, 26)`, and never use generated labels as later bases. For threshold logic, cap values above 40 at 40 and write excess as `value - 40`; otherwise leave the source unchanged and omit excess.
- For marker trimming, remove only the complete prefix above the first marker while preserving the marker and following rows unless deletion is requested. Remove all literal double quotes when required, use variable-position parsing rather than fixed offsets, and complete all workbook edits before saving.

## Verification

- Reopen the saved workbook, preferably after recalculation and in both formula (`data_only=False`) and value (`data_only=True`) modes. Verify the exact output path, file existence, sheet names and positions, active sheet when relevant, dimensions, merged-cell handling, headers, target bounds, and unchanged unrelated content.
- Read back every cell in the requested range, including blanks, zeros, formulas, cached values, datatypes, first and last rows, sparse blocks, totals, endpoints, and representative middle rows. If the library cannot evaluate formulas, recalculate with a spreadsheet engine or write validated static values when evaluated results are required.
- Confirm source and destination mappings, authoritative ID membership and order, placeholder fields, complete row widths, selected-column order, compactness, absence of gaps or stale trailing output, duplicate retention, composite-key behavior, and aligned paired fields.
- Verify date cutoffs and boundary inclusion, lookup match mode and full ranges, anchored versus relative references, wildcard and membership criteria, cumulative starts, formula priority, blank or zero fallbacks, correct return columns, and absence of circular or obsolete references.
- Confirm every repeated block and final populated record was processed; marker intervals have valid boundaries and consecutive markers behave correctly; preamble removal preserved the marker; first-match, last-match, group-transition, and section-boundary behavior is correct.
- Validate expansions, insertions, deletions, sorting, and compaction against original row snapshots: expected counts, adjacency, source order, stable identifiers, retained row multisets, blank inserted rows, protected headers, separators, and no skipped rows. Confirm generated labels were not reused as bases and grouped ranks and ties are scoped correctly.
- Verify copied or relocated cells retain expected values, formulas, styles, number formats, alignment, widths, heights, dimensions, and protections; value-only edits did not restyle or restructure the workbook. Confirm unmapped values remain unchanged, dependent formatting was applied only to valid replacements, frequency ties use first appearance, and totals are compared with an appropriate tolerance rather than exact floating-point equality.

## Common Pitfalls

- Do not assume sheet names, active sheets, worksheet order, headers, column letters, fixed ranges, dimensions, marker spacing, lookup uniqueness, or output locations; inspect the actual workbook first.
- Do not edit headers, totals, merged or unrelated cells, rows outside requested bounds, existing correct results, or intentional separators. Do not leave stale output after a shorter result or write outside the requested destination.
- Do not use partial keys for duplicates, global ranking or tie counts, one group value for multiple row-level records, or positional offsets when explicit identifiers and criteria are available. Do not stop at the first block, first duplicate, or first matching row when all matches are required.
- Do not confuse exact, substring, containment, prefix, suffix, and case-insensitive matching; do not call string methods on non-string cells or treat formatted blanks as populated values. Do not use broad substring searches for exact suffix tasks.
- Do not apply filters in separate write passes, omit combined criteria, use inclusive month ends, derive relative dates from today when the data maximum is required, or omit the final populated record. Do not use one-dimensional matching for a two-dimensional lookup.
- Do not copy values without required formatting during relocation, discard styles during compaction, or restyle value-only edits. Do not transform one field without its associated fields or apply dependent formatting before validating the replacement.
- Do not reprocess generated rows, use unsafe duplication counts, insert or delete rows top-to-bottom, sort live worksheet cells, reuse generated labels as inputs, cross blank continuation boundaries, or overwrite existing indices.
- Do not use shifting lookup ranges, arbitrary full-column formulas, circular target references, formula text as proof of evaluated results, literal-text tests for Excel errors, exact equality for floating-point totals, or an intermediate filename. Recalculate when needed, save to the exact required path, reopen the file, and verify the complete result.
