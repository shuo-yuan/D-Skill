Use a repeatable inspect → plan → execute → verify script. Follow these steps:\n\n1. **Inspect the workbook first.** Load the workbook, enumerate sheet names, dimensions (`max_row`, `max_column`), used range, headers, populated cells, merged cells, existing formatting, representative rows, source/target areas, and any summary/total rows. Do not assume structure from task descriptions; use `iter_rows(min_row=..., max_row=..., values_only=True)` for efficient scanning.\n\n2. **Determine exact data ranges and mappings.** Identify header rows, data blocks, intentional blank separators, repeated headers, and trailing constraint rows. Scan rows sequentially; start a block when non-header/non-blank data appears and end at the next blank row or recognized header. Use observed worksheet bounds, not hardcoded row counts. For repeated markers or intervals, track the previous marker and compute `last + 1` through `current_row - 1`; empty intervals return `0`. Map output blocks explicitly before writing (see `### Output Block Mapping` below).\n\n3. **Plan all transformations together.**\n   - Combine inclusion/exclusion filters in one predicate; apply all criteria at the same time. Use inclusive boundary comparisons (`start <= value <= end`) unless the task demands exclusive bounds. For relative dates, compute the cutoff from the maximum valid date in the column, not from today's date.\n   - Match keys before writing: scan the target column from the top down unless a different direction is specified; stop at the correct case-insensitive substring/exact match and never assume a fixed row. For row-and-column dependent results, use composite-key matching (e.g., tuple of row key + column header).\n   - For grouping/deduplication, use composite keys (tuples of all identifying columns) as dictionary keys. See [references/deduplication-pattern.md](references/deduplication-pattern.md).\n   - For formula writing, choose the simplest reliable strategy: direct cell references for small fixed ranges; structured/dynamic formulas for larger ranges. Lock fixed ranges with absolute references and use relative references for row-dependent criteria. See [references/formula-patterns.md](references/formula-patterns.md).\n   - Infer layout patterns from already-filled example cells (column pairs, step sizes, rows per record) and derive a deterministic repeatable rule.\n\n4. **Execute only within detected data ranges.**\n   - Modify only specified output cells and preserve headers, totals, formatting, and unrelated content. Use direct value assignment (`ws.cell(row, col).value = ...`) rather than rebuilding/duplicating worksheets. For sheet-by-number tasks, operate on `workbook.worksheets[n-1]`.\n   - Clear the target/destination region before repopulating to prevent stale data; when copying, only overwrite destination cells if the source cell is non-blank (not `None` and not empty string).\n   - For transposition/flattening, collect all matching records, flatten source columns in order, and pack them in a deterministic layout.\n   - For thresholded allocations, split excess explicitly: `if value > threshold: source = threshold; destination += value - threshold`.\n   - For row insertion/deletion, process targets in descending row order; prefer worksheet row deletion over value compaction when the task says delete rows.\n   - Preserve formatting when moving/copying cells; copy values, styles, number formats, alignment, and column widths together. When applying requested formats, change only the requested attribute unless the task explicitly changes more.\n   - Use `str(v).casefold()` for case-insensitive partial matches; use full-cell substring membership for \"contains\" requirements and direct prefix checks for \"begins with\" requirements.\n   - Keep paired/grouped data aligned: sort as `(col_a, col_b)` tuples or snapshot-sort-write back.\n\n5. **Recalculate only if formulas are needed.** `openpyxl` does not evaluate formulas. Either compute final values in Python and assign them, or run a guaranteed recalculation step (e.g., `recalc.py`, LibreOffice headless, Excel) before verification. Prefer computed numeric/string values unless formulas are explicitly required or recalculation is guaranteed.\n\n6. **Save and verify.** Save the workbook to the exact required output path; ensure the requested sheet is active on save, and do not rename/move/modify the filename. Then re-open/read back and run the Verification checklist.\n\n### Row Synchronization\nWhen aligning rows across sheets using a key ID column, treat the source ID list as authoritative for ordering and membership:\n1. Load source IDs in order.\n2. Map existing target rows by key ID, preserving each complete row.\n3. Build output rows by iterating source IDs: use the preserved row if the ID exists; otherwise insert a placeholder row `[ID] + [None] * (total_columns - 1)`.\n4. Write all rows in source ID order. Do not append only unmatched rows; do not overwrite existing rows.\n\n### Output Block Mapping\nFor each required output block/range, record before writing:\n- Item column, account-reference column, amount column, source matching key, total row (if any), and data range.\n- Do not infer the account/reference column from `start + N` offsets; use the header that matches the source data key.\n- Store the mapping and reference it in every later step.## Core Workflow

- Load the workbook with `openpyxl.load_workbook()` and enumerate sheet names, dimensions (`max_row`, `max_column`), used range, headers, populated cells, data types, merged cells, existing formatting, and representative values before any edit. Use `iter_rows(min_row=..., max_row=..., values_only=True)` for efficient scanning.
- Select the exact worksheet and data-row range specified or observed; do not rely on task descriptions or abbreviated previews. Watch for typos such as `OUPUT` vs `OUTPUT`.
- Scan rows to detect data blocks using blank rows and repeated/recognized header rows as boundaries. Distinguish intentional blank separator rows from redundant empty rows. Locate header row, first and last nonblank rows, and trailing summary/constraint rows before bulk edits.
- Inspect current values, formatting, and data types of target ranges before changing them. If the destination already contains the required values, preserve/compare representative rows instead of regenerating.
- Unmerge all relevant merged cells before placing formulas into requested cells.
- **Case-insensitive matching:** Normalize both cell text and target phrases with `str(v).casefold()`; use full-cell substring membership when a target may appear inside a longer/comma-separated string.
- **Prefix and delimiter checks:** Use direct string prefix checks (`str(v).startswith('Z1')`) for `begins with`; when extracting substrings from variables, split on known markers and next delimiters, then trim whitespace, not fixed character positions.
- **Numeric columns:** Validate/parse cells before arithmetic; start below header rows and skip/handle text/non-numeric values without aborting.
- **Date/type awareness:** Inspect whether date cells are strings, strings with time suffixes, or datetime objects; normalize before sorting/comparing.
- **Formatting-aware selection:** When selecting cells by fill/color, require both the target format and a nonblank value; exclude formatted-but-empty cells.
- **Literal value searches:** Restrict searches to the exact column/row range specified; inspect literal cell contents rather than formula result text when the task is about literal values.
- **Column relationships and duplicate identity:** Identify which columns are keys, criteria ranges, and sum ranges, including non-contiguous event columns. For duplicate detection, count occurrences of the key column(s) with `collections.Counter` or group by all identity fields; retain every row whose composite key count > 1.
- **Last occurrence / keep-last-per-group:** Scan bottom-to-top, track seen values in a set, and keep the first (bottom-most) instance.
- **Workbook order and boundaries:** When a summary/boundary sheet exists, process only worksheets appearing before it, and exclude the boundary sheet itself.
- **Relative-date cutoffs:** Compute cutoffs from the maximum valid date in the target date column, not today's date.
- **Candidate sum/value matching:** When a target value may be formed by multiple cells, enumerate candidate subsets programmatically and accept combinations within a numeric tolerance; avoid visual guesses or assuming a fixed number of cells.
- Confirm the edit rule actually matches the observed layout/key-column values before running a workbook-wide transformation.## Inspection

### General Principles\n- Modify existing workbooks in place by loading and assigning cell values; avoid rebuilding/duplicating sheets. Preserve headers, formatting, and unrelated cells. If a separate output file is required, write to the exact output path and preserve the source.\n- Modify only specified output cells; explicitly clear the target range and any stale rows/columns before repopulating. Clear nonmatching result cells or set them to `None`.\n- Convert zero-based data indexes to one-based worksheet row numbers before writing.\n- Save once at the end to the exact required output path; ensure the requested sheet is active on save.\n\n### Data Manipulation and Filtering\n- Use direct comparisons/exact string matching for rule-based replacements; include a fallback branch for rows that match some but not all criteria.\n- Use mapping dictionaries with fallback for categorical replacements (`mapping.get(value, value)`). For text cleanup, use literal string replacement such as `cell.value.replace('\"', '')`.\n- Apply filters inclusively (`start <= value <= end`) unless exclusive bounds are specified; combine all criteria in one pass.\n- Apply prefix filters with `isinstance(value, str)` and `startswith(...)`.\n- Copy only the requested source columns; write qualifying rows consecutively starting at the specified destination. Preserve source order.\n- When copying/moving cells, transfer both values and formatting: styles, number formats, alignment, fonts, fills, borders, protection, column widths, row heights. Use `copy()` on openpyxl cells where appropriate.\n- Keep paired/grouped rows aligned; for sorting, normalize date representations to comparable datetime keys and sort multi-key records with tuple keys.\n- For row compaction, collect nonblank rows and write sequentially to a contiguous range, then clear old trailing rows. Prefer worksheet row deletion over compaction when the task says delete rows.\n\n### Clearing, Repopulating, and Row Operations\n- Identify the total/summary row first; clear only data rows above it, and restore TOTAL label/formula if accidentally cleared. Never overwrite the total row with data.\n- For column-wide transformations, iterate only over identified data rows (`for r in range(first_data_row, last_data_row + 1)`), not headers or constraint rows.\n- Delete rows by condition or duplicate removal bottom-up (`for row in range(last, first, -1)`) to avoid index shifts. Before deleting, collect targets and validate all conditions/compound conditions. When deleting all rows above a marker, delete the complete prefix; stop before the marker row itself.\n- When inserting blank rows into a formatted worksheet, copy row height, hidden state, and cell styles from the neighboring source row. Process insertions in descending order.\n- For safe row deletion/insertion patterns, see [references/row-operations.md](references/row-operations.md).\n\n### Lookups, Grouping, and Aggregation\n- Build in-memory lookup maps from lookup-table rows before processing main data.\n- Use composite keys (tuples of all identifying columns) to avoid merging rows that should remain separate. Preserve first-seen group order and aggregate value columns.\n- When lookup keys repeat, collect ALL matching records unless the task explicitly requires first/ordered match; do not stop at the first match. Preserve source order for duplicates.\n- For multi-column lookups/transposition, flatten each matching record's value columns into one ordered sequence before writing across consecutive output cells.\n- **Non-unique key warning:** Never use a group-level key (e.g., race/meet ID) to map one source row to many destination rows; use a row-level relationship such as unique ID, rank, or explicit ordering.\n- For unpivoting selected wide columns, retain identifying columns and emit one row per selected variable column.\n- When duplicating rows by a count column, snapshot source row locations first; for each source row read the count and use `max(1, int(count))` with a default of one copy; emit all copies consecutively before moving to the next source row.\n- **Downward fill:** Enforce boundary conditions; only fill blank cells, skip cells that already contain values, and copy only when both current and preceding rows satisfy the continuation criteria.\n- For conditional aggregation with OR-list matching, use `SUMPRODUCT` with `ISNUMBER(MATCH(data_range, criteria_list, 0))` to create a Boolean mask; do not pass a criteria range directly to `SUMIFS` as a single criterion.\n- Date lookups on sorted historical data: use approximate match (`MATCH(...,1)` or `VLOOKUP(...,TRUE)`) for latest prior value; use inclusive lower and exclusive upper bounds for monthly ranges: `date_range>=month_header` and `date_range<EDATE(month_header,1)`.\n\n### Formulas and Recalculation\n- `openpyxl` does not calculate formula cells. Write computed final values in Python unless a recalculation step (e.g., `recalc.py`, LibreOffice/Excel open/save) is guaranteed before delivery. If formulas are appropriate, place the formula in the exact cell and recalculate afterward.\n- Use `SUMIF` for single-criterion conditional sums and `SUMIFS` with one criteria range per condition for multiple criteria; do not use `COUNTIFS` when a sum is required.\n- Prefer direct cell references (e.g., `=A25`) when the target range is small and explicitly specified.\n- Lock fixed source/date/lookup ranges with absolute references (`$B$2:$B$8`); leave row-dependent criteria relative.\n- Use `IF(cell<>\"\", transform, \"\")` or `IF(AND(value<>\"\", category<>\"\"), ..., \"\")` to avoid output on empty rows.\n- For text inside longer/comma-separated cells, use wildcard criteria `\"*\"&cell&\"*\"`.\n- For cumulative/running formulas, use expanding mixed-reference ranges (`$A$2:A{r}`) so the start row is locked and the end row expands when copied.\n- For row-keyed two-dimensional lookups, prefer `INDEX`/`MATCH` over nested `IF` chains; wrap in `IFNA(..., 0)` or `IFERROR(..., \"\")`.\n- For repeated labels across categories, combine Boolean criteria with multiplication: `MATCH(1, (category_range=selected_category)*(expense_range=selected_expense), 0)`.\n- For ranking with ties within groups (descending), use `COUNTIFS` for strictly greater values in the same group plus a cumulative `COUNTIFS` for equals through the current row. Wrap in an `IF` that checks required nonblank cells.\n- For ranked allocation with ties, use `IF(value=MAX(range), total_points/COUNTIF(range,MAX(range)), 0)`.\n- For distinct-count tasks, use `=COUNTA(UNIQUE(FILTER(range, range<>\"\")))`.\n- For exact right-anchored text tests, use `=RIGHT(A2,LEN(B2))=B2`.\n- For piecewise proportional scaling (e.g., positive values to [0,+5] and negative to [-5,0]), use `5*x/max_positive` for nonnegative inputs and `5*x/abs(min_negative)` for negative inputs. Do not add an extra minus sign to the negative branch.\n- For error-aware formulas, use `ISERROR`, `ISERR`, or `IFERROR`; never compare Excel errors to literal strings such as `error`.\n- For formula blocks, generate row-specific formulas programmatically; confirm the formula is in the exact requested cell and confirm the last populated row is included in all ranges.\n- For aggregate outputs, write per-sheet aggregates as direct values; if recalculation is guaranteed, final combined totals may be spreadsheet `SUM` formulas so they update automatically.\n- Apply formulas only where results are requested; explicitly clear result cells/set them to `None` for non-requested rows.\n\n### Formatting and Finalization\n- Keep value transformation and formatting separate; apply formatting only after the written value is validated as nonempty.\n- Change only the requested formatting attribute (e.g., font family) and leave other formatting intact unless explicitly instructed. When applying number formats to modified cells, set them explicitly (e.g., `m/dd/yyyy`, `0.00;-0.00`) and do not rely on inherited formatting.\n- Apply formatting only to the target output range, excluding headers/unrelated cells unless the task includes them.\n- Copy source cell styles and dimensions when building aggregated output; then apply custom number formatting to aggregated numeric columns.\n- For cumulative/priority formulas, nest conditions in the exact task-specified priority order.\n\n### Data Manipulation Guidelines\n- Identify the header row and start data transformations from the row immediately after it (usually row 2) unless instructed otherwise.\n- Use explicit row ranges (`for r in range(2, sheet.max_row + 1)`) to exclude headers.\n- After transformations, validate first and last rows of the affected range to ensure headers/boundaries were not changed.\n- For live reorder/sort operations, never write back directly from live worksheet `Cell` objects obtained from `iter_rows`. Snapshot row data (values plus styles) into independent tuples/dicts, sort, write back in a separate pass, then verify by comparing multiset of row identifiers or full row tuples before and after.## Writing Output

After every output block, run this checklist:\n1. Headers and labels exactly match the task's required terminology and source descriptions.\n2. First and last data rows and boundary rows match expected criteria/data, especially inclusive filter boundaries.\n3. Total/summary row remains present and non-empty, with formulas where required.\n4. Record counts / nonblank populated rows match expected source count; required blocks are not empty.\n5. No stale rows/columns remain in cleared destination range.\n\nAdditional checks:\n- Confirm the output file exists at the required path with a filesystem listing and nonzero size; confirm the requested sheet is active on save.\n- Reopen the workbook and read back modified cells. Assert exact intended values (e.g., `assert sheet['J35'].value == 1500`); if a cell contains a formula string instead of a value, perform/confirm recalculation before submitting.\n- For formula cells, recalculate with an external engine (`xlcalc`, LibreOffice headless, or `recalc.py`) and reopen with `openpyxl(data_only=True)`; verify cached computed results, not formula text. Spot-check formulas in at least two non-adjacent cells to ensure lookup ranges did not shift.\n- Use tolerant numeric comparisons: convert amounts to float and test `abs(actual - expected) <= tolerance`, not exact equality.\n- Validate the entire answer range, not just manually edited cells; dependent formulas may lose cached values. Derive ranges from actual data extent, not truncated previews.\n- After writing values, read back before applying dependent formatting; verify formatting only on cells where target value is present.\n- Verify moved/inserted headers and data appear in intended location; totals/dependent values remain intact.\n- After sorting/reordering paired data, spot-check 2-3 rows to confirm Column A and Column B correspond; validate row order against authoritative ID list where applicable; blank placeholder rows exist for missing IDs.\n- After row deletion/insertion, verify the full requested range cell by cell, including blank cells: confirm headers, records, blank separators, and trailing rows match expected structure; sheet dimensions updated correctly.\n- Verify blank formatted source cells were not copied; formatting is applied to all populated output cells; copied rows retain styles, number formats, alignment, column widths.\n- For piecewise scaling, check sign and boundary invariants: max maps to +5, min maps to -5, zero maps to 0, and all signs are preserved.\n- Before/after generation, verify intervals satisfy `start_row <= end_row`; empty intervals return `0`, never `start > end`.\n- If output derives from aggregation/lookups, spot-check a few rows against original data; include group transitions and final row.\n- Confirm headers and labels are unchanged and match source wording exactly.\n- For advanced robust patterns (date cutoff, format-preserving transfers, worksheet-by-position), see [references/robust-patterns.md](references/robust-patterns.md).## Verification

- **Fixed-range/hardcoded coordinate assumptions:** Hardcoding rows/columns breaks when data changes or columns move. Always inspect and use dynamic ranges; recompute source/target indices after insert/delete.\n- **Editing without inspection:** Wrong sheet/range from assuming structure. Read actual sheet names, headers, dimensions, and representative values first.\n- **Header and boundary errors:** Forgetting to exclude header rows, modifying/deleting a total/constraint row, assuming all blank rows are removable, or deleting the matching row itself when deleting rows above a match.\n- **Header/label mismatch:** Use exact source terminology for output headers and labels; do not singularize/pluralize or otherwise normalize wording unless explicitly required.\n- **First-match / direction mistakes:** Picking a later or earlier match when the task requires first occurrence, upward/downward search, or an ordered conditional lookup. Scan in the specified order and stop at the first qualifying result.\n- **Exact vs containment and case mistakes:** Using exact equality when the spec says look for/contains; using case-sensitive comparisons instead of `casefold()`; splitting compound/comma-separated text when full-cell substring matching is needed.\n- **Independent column sorting / misaligned pairs:** Sorting Column A without Column B scrambles row associations. Sort paired tuples or snapshot full rows.\n- **Row deletion pitfalls:** Top-to-bottom deletion shifts indices; delete bottom-up. Single-condition deletion may remove associated data; use compound conditions. Confusing delete everything above marker with delete only blank rows above marker.\n- **Row synchronization pitfalls:** Appending unmatched records instead of iterating authoritative IDs; overwriting existing rows instead of mapping/preserving key-ID rows.\n- **Clearing/stale output:** Failing to clear destination before writing; failing to clear old trailing rows; saving multiple partial files.\n- **Formatting pitfalls:** Copying only `.value` loses formats; applying formatting before validating value; relying on inherited formats; modifying the wrong format attribute; applying formatting to headers/unrelated cells.\n- **Formula pitfalls:**\n  - `openpyxl` does not evaluate formulas; always write computed values or run a guaranteed recalculation step.\n  - Checking formula text instead of displayed/cached results.\n  - Mixed references and cumulative ranges: lock the start row (`$A$2:A{r}`).\n  - Shifting lookup ranges from relative references; use absolute references for lookup/source ranges.\n  - `COUNTIFS` when a sum is required; use `SUMIF`/`SUMIFS`.\n  - OR-list matching with `SUMIFS` criteria ranges; use `SUMPRODUCT` + `ISNUMBER(MATCH(...))`.\n  - Wrong priority order in nested conditionals; nest in task-specified precedence.\n  - Comparing Excel errors as literal strings; use `ISERROR`, `ISERR`, or `IFERROR`.\n  - Sign loss in piecewise scaling: do not add an extra leading minus to the negative branch.\n  - Reversed/empty intervals: return 0 for empty intervals; do not create formulas with `start > end`.\n  - Full-column range misuse: avoid `N(A:A)` etc.; use bounded ranges.\n  - Blank-cell arithmetic: convert blanks to zero and align coefficient vectors.\n  - Hand-writing per-cell special cases instead of one systematic formula block.\n- **Lookup/grouping pitfalls:** Single-key lookup for two-criteria results; non-unique group key mapping one source row to many destinations; using a helper column as sort key; using source row numbers after reordering (regenerate sequential numbers).\n- **Stopping at the first table:** Repeated headers/blank separators hide valid later data; scan the full used range.\n- **Date/type pitfalls:** Off-by-one dates from strict `<`/`>` instead of inclusive `<=`/`>=`; not normalizing date strings/datetime types; treating numeric strings inconsistently; confusing cell references with cell values and text types. Test both actual numbers and strings convertible to numbers via `float()`.\n- **Sequential transformations:** Reading previously written output as input for later rows; derive state only from original data. See [references/sequential-transform-patterns.md](references/sequential-transform-patterns.md).\n- **Save/output path:** Saving to wrong path or inactive sheet; overwriting source when a separate output file is required.\n- For safe row deletion patterns, see [references/row-operations.md](references/row-operations.md).## Common Pitfalls
