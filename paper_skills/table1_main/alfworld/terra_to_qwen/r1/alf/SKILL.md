## Core Approach


- Prefer high-level, goal-specific actions (e.g., 'heat X with microwave', 'move X to coffeemachine') when they appear in the admissible action list. Do not decompose them into primitive steps (open, take, put) unless the high-level action is absent.
- When a task names a specific object, navigate directly to the surface where it is most likely found based on the initial room scan. Before picking up the object, verify that the current observation lists a 'take...from...' option for it.
Also confirm that the object's type name matches the goal's required type exactly (e.g., 'mug' not 'cup'). Do not pick up a similar but differently named object unless you have exhaustively searched and confirmed no exact match exists.

## Task Decomposition

Before taking any action, break the instruction into an ordered list of subgoals (e.g., find object, apply transformation, move to target). After each action, ask: "Which subgoal am I working on? Is my current action moving me closer to completing it?" This keeps every step purposeful and helps recognise when a subgoal is finished.

Runtime check: Before moving to a new location or taking a new object, restate the full subgoal chain and confirm you have completed the previous step. Only advance when the previous step is done.
## Precondition Chains


For tasks that describe an object relative to another, secure the primary object first. For cleaning tasks, take the object immediately and clean before placing.

## Precondition Chains

For tasks that describe an object relative to another ("X under Y", "X on Y", etc.):
- Identify the primary object (the one you must ultimately examine/manipulate) and the reference object.
- Before moving to the reference object, **secure the primary object** (take it into inventory or hands).
- At each step, ask: "Do I currently hold the primary object?" If not, find and take it first.
- Only then go to the reference object and perform the final interaction.

- **Cleaning precondition**: If the task description includes "clean <object>", do not assume the object is already clean. When you locate the object, **take it immediately** before leaving its current location. Then go to a cleaning receptacle (e.g., sinkbasin) and use the `clean <object> with <receptacle>` action before heading to the final destination. Confirm cleaning via observation (e.g., "You clean the …") before moving on. After cleaning, if `move <object> to <receptacle>` is admissible, navigate to that receptacle and execute the move immediately. **Runtime check:** After seeing the target object, ask: "Am I holding the object now?" If not, take it immediately. Before placing any object whose goal description includes "clean", verify: "Did I perform a cleaning action on this object?" If not, go to a cleaning station and clean it first, even if the object appears clean.

## Action Validity & Recovery


- Before emitting any action, verify it is present verbatim in the current 'Your admissible actions' list. Never attempt an action that is not listed.
- Minimize redundant actions: Only use `inventory`, `look`, or `examine` when you need a specific fact that will change your next action. Before using them, state what you need to learn and what you'll do differently based on the result. If you cannot, skip the action.
- After a subtask succeeds (e.g., heating, cooling, cleaning), trust the confirmation and immediately move to the next subtask. Do not close, reopen, inspect, or repeat the action.
- **Prefer plain `move` for placement tasks:** When the task says "put X in Y" or "place X on Y", always check the admissible actions for a `move X to Y` command first. Avoid using appliance actions like `cool` or `heat` at the destination unless the task explicitly requires heating/cooling and no `move` is available. Using unnecessary side‑effect actions causes semantic drift and wastes steps.

- **Output discipline:** When you are ready to act, output **exactly one** admissible action inside `<action>` tags. Do not append any extra text, actions, or characters after the closing tag. Verify that your response ends with `</action>` and contains only one `<action>…</action>` pair before sending.
- **Plan‑action consistency check:** Before submitting, re‑read the action inside `<action>` and confirm it matches the action you reasoned about. If it differs, correct it. Runtime check: after writing the `<action>` tag, silently ask: "Is this exactly the action I reasoned about?"

- **Infer capacity limits:** When holding an object, if `take <item>` is absent from admissible actions, you may be at capacity. Go to the target destination and place the held item before attempting to pick up another item. Do not repeatedly try the same take action.

- **Container precondition:** Before using `take <item> from <container>`, verify that the container is open. If the observation does not explicitly state it is open, open it first. Never attempt to take from a closed container.
- If a desired action (e.g., heat, cool, clean) is not in the admissible list, navigate to the appliance or receptacle associated with that action to make it available.

- If the action you need is not in the admissible list, do not attempt it. Instead, select a listed action that advances the state (e.g., go to the target location, open a container, or take inventory) rather than trying an unlisted command.

- **Action-subgoal alignment check:** After reasoning about the next subgoal, before submitting the action, silently verify that the chosen admissible action's verb and object match that subgoal (e.g., 'clean … with …' not 'look'). If it does not, re‑examine the admissible actions list and select the correct action.
## Task-Type Procedures


- **Heating food**: When you need to heat a food item (e.g., tomato, potato), go to the microwave and use `heat <object> with microwave` as soon as you possess the object. This is the most efficient pattern.

- **At the appliance**: When you arrive at the microwave (or any heating appliance) with the object, scan admissible actions for `heat <object> with <appliance>` and execute it immediately. Do not open, close, or manually place the object inside the appliance.

- **Retrieving perishable food**: When the task requires a perishable food item (e.g., tomato, lettuce, apple, egg), go directly to the fridge, open it, and take the item as the very first steps. Do not search other containers first unless the fridge is empty or absent. If a fridge is listed in the initial observation, make `go to fridge` your first action, then `open fridge`.

- **Cooling food**: When you need to cool a food item (e.g., tomato, pot), go to the fridge and use `cool <object> with fridge` as soon as you possess the object. Do not open the fridge first; the cooling action works even when the fridge is closed. Only open the fridge if the `cool … with fridge` action is not in the admissible list. Runtime check: upon arriving at the fridge with the object, scan admissible actions for `cool … with fridge` and execute it immediately.

- **Search stove burners first for pots/pans:** When the goal is to cool a pot or pan, before opening any cabinets or drawers, visit all stove burners in the area. The object is likely on a heat source. Move to each burner and check admissible `take` actions from that burner, as they may reveal nearby pots. Only after exhausting stove burners should you search other surfaces and containers. **Runtime check:** Before opening a cabinet or drawer for a cooling task, ask: “Have I visited every stove burner and checked for relevant `take` actions?”

- **Microwave retrieval caveat:** If you take the object from inside the microwave (e.g., after opening it), the object is not yet heated. You must still execute `heat <object> with microwave` before moving to the destination. After taking, immediately scan admissible actions for the heat action and execute it before leaving the appliance.

- **Cooling food with perishable items**: If the item to be cooled is perishable (e.g., bread, tomato), first go to the fridge to retrieve it (see Retrieving perishable food) before cooling. This avoids extra search steps.

- **Runtime check for perishable food:** Before starting any search, ask: 'Is the target object commonly kept in a fridge (e.g., tomato, bread, apple)?' If yes and a fridge is in the environment, make `go to fridge` your first location action.

- **Prefer dedicated temperature-change verbs:** When at a cooling or heating appliance (fridge, microwave, etc.), always scan admissible actions for a dedicated verb (`cool ... with ...`, `heat ... with ...`) and use it instead of a plain `move` action. Do not use `move` to place the object inside the appliance if a dedicated action is available. Runtime check: before issuing `move`, confirm no `cool`/`heat` action is present.
## Common Pitfalls


- **Skipping open surfaces:** Do not go straight to cabinets or drawers. Always check open surfaces and the target receptacle first. **Runtime check:** Before choosing any action that opens or goes to a closed receptacle, list all `go to countertop N` or `go to shelf N` actions in the admissible set; if you have not yet been to every one of them, go to the next unvisited surface first.
- **Misreading surface emptiness:** "You see nothing" on a cabinet does not mean it is empty. Open or examine it before moving on.
- **Deposit goal items immediately:** After taking an item that belongs at a target receptacle, your very next action must be `go to` that target location. Upon arrival, if the target receptacle is a container (drawer, cabinet, etc.), verify it is open. If it is closed, use the available `open` action before attempting the move. Do not insert `look`, `examine`, or any other action before moving. If `move <object> to <receptacle>` is admissible once there, execute it immediately. Do not carry goal items around while exploring other locations. After every `take`, check if the item is a goal object and, if so, place it at the target immediately.
- **Unnecessary examination at destination:** When you arrive at the target receptacle while holding a correctly prepared object, skip `examine` and `look` actions. If `move <object> to <receptacle>` is admissible, execute it immediately.
- **State adjectives are transformations, not location clues:** When a task includes adjectives like "cool," "hot," "chilled," or "sliced," treat them as actions to perform on the base object after acquiring it. Search for the base object on all surfaces and containers, not only the appliance associated with the adjective. Once you have the object, use the appropriate appliance to apply the transformation. Before deciding where to search, ask: "Is this adjective telling me where the object is, or what I must do to the object after I find it?"
- **Fetch one object at a time:** Once you pick up an object, do not attempt any `take` action until you have deposited the first at its destination. After every `take`, go directly to the target location and use `move <object> to <receptacle>`. Before attempting a new `take`, use `inventory` to confirm you are empty‑handed. This prevents deadlocks where `take` actions disappear because you are already holding something.
- **Skipping closed containers:** After checking all open surfaces, systematically open every closed drawer, cabinet, or box listed in the admissible actions. Do not skip any; the target object may be inside. Before leaving a location, ask: "Have I opened every closed container here?"
- **Redundant `inventory` and `look`:** Never use `look`. The environment provides object lists automatically. Use `inventory` only after picking up or placing an object. Before using `inventory`, confirm a recent state change. If none, proceed to the next unexplored container or surface.
- **Substituting similar object types:** When the goal specifies an exact object type (e.g., "pencil"), do not pick up objects with a different type name (e.g., "pen") unless you have exhaustively searched all accessible locations—including opening every closed container and checking all surfaces in the predefined order—and confirmed that no object with the exact type exists. Before taking any candidate, compare its type word to the goal's required type word character‑by‑character, ignoring numeric suffix. Only after exhausting all locations may you consider a similar object.
- **Delivering without transformation:** Immediately after picking up an object that requires a state change (clean, cool, heat, slice), navigate directly to the appropriate appliance with the object in hand. Do not first go to the target location. Before placing the object, confirm that all required transformations have been performed and the object's state matches the goal adjective. (Example: 'put a clean apple on the diningtable' → clean the apple at the sink before heading to the diningtable; 'put a cool bread on countertop' → cool bread with fridge before moving it.)
- **Assuming heating from appliance context:** If the task goal contains 'heat' and you find the target object inside a microwave or stove, do not assume it is already heated. After taking the object, immediately check admissible actions for a `heat <object> with <appliance>` command and execute it before moving the object to its destination. Before placing the object, verify that a heat action appears in your recent action history. This applies even if the object was already inside the appliance.
- **Overthinking identical objects:** When multiple instances of the same object type are visible (e.g., `alarmclock 2` and `alarmclock 3`) and the goal does not specify a particular instance ID, pick the first available in the admissible actions without deliberation. Before spending a second reasoning step on which instance, confirm whether the goal names a specific instance; if not, act immediately.
- **Redundant actions after key interaction:** After performing the central action of the goal (e.g., `use desklamp`, `put`, `heat`), do not add extra `examine`, `look`, or `take` actions to confirm unless the observation indicates failure. Before taking any action after the key interaction, ask: "Has the goal's main verb already been performed? If so, does the last observation indicate a problem?" If not, stop or proceed to the next subgoal without extra checks.
- **Redundant inspection after subtask completion:** After finishing a cleaning, heating, or cooling action, immediately navigate to the next destination. Do not insert `look` or `examine` unless you are unsure where to go. Ask: "Do I already know which receptacle to go to? If yes, go there now."
- **Unnecessary examination of held objects in composite goals:** When the task requires using a held object together with another object (e.g., 'examine X with Y'), after picking up X, do not examine X alone. Instead, go directly to the known or likely location of Y. Only examine X once Y is confirmed present in the current view. Before acting, ask: 'Does the goal involve another object? If yes, and I just obtained one required object, is my next action directly seeking the other object?' Also, before issuing any `examine` action on X, ask: 'Does the goal name a required tool that I have not yet picked up or used?' If yes, postpone the examine and navigate toward that tool.
- **Taking without moving:** Do not attempt `take <object>` without first navigating to the container and verifying the object is listed in the current observation. Always `go to` the container before taking.
- **Revisiting already-searched locations:** After checking a container or surface and confirming the target is not there, do not return to it later unless you have a specific reason (e.g., you placed an object there). Before moving to a location, confirm it is not on your visited list unless new information makes it relevant.
- **Extraneous actions after acquiring an object:** After taking an object that requires cleaning, heating, cooling, or slicing, move directly to the relevant appliance without inserting `look`, `examine`, or `inventory`. The next sub-goal is clear; do not delay.
- **Wandering after picking up X in lamp tasks:** When the goal is to look at or examine an object under a lamp (e.g., desklamp), after taking the object, go directly to the lamp's location and use the lamp. Do not put the object down or explore other containers. The lamp is typically on a desk or table; navigate there immediately.
- **Wandering when all required objects are present:** If the current observation shows all objects needed for the current subgoal (e.g., a target object and a device to use it with) and admissible actions include the necessary `take` and `use` commands, do not move to another location. Complete the subgoal immediately. Before any `go to`, ask: "Do I already see everything I need here?" If yes, act on them without leaving.
- **Using facilities with held objects:** When the goal is to "look at <object> under <facility>" or "use <facility> with <object>", and you are carrying the object and have just reached a location that contains the facility, use the facility immediately if the admissible actions list contains `use <facility>`. Do not insert extra `examine` or `look` actions. Runtime check: if you hold the target object and see `use <facility>` in the admissible actions, choose it immediately.
- **Goal placement self-check:** After every `take`, ask aloud: "After I take the object, is my next action going straight to the goal location and placing it, or am I wandering away to look at something else?" If the answer is not the goal location, re‑evaluate your next action.
- **Leaving a found object behind / Delaying take when object is visible:** If the observation lists the target object, take it immediately. Do not navigate to another location before taking it. Scan each arrival observation for the target; if present, issue the take action now. Runtime check: "After moving to a location, do I see the target object name in the observation? If yes, take it now."
- **Take primary object immediately in composite tasks:** When the task involves using one object with another (e.g., examine X with Y), if you see X during search, take it immediately before searching for Y. This ensures the main object is ready once the tool is found.
- **Concrete wrap‑up routine:** After taking the target object, your next action must be `go to <target>` and the following action must be `move <object> to <target>`, with no other actions in between.
- **Unnecessary appliance manipulation:** When you are at an appliance and the admissible actions list a transformation command (`heat`, `cool`, `clean`) for the object you are holding, execute that command immediately. Do not open, close, `look`, or manually place the object. Runtime check: if a direct transformation command is available and you hold the object, select it now.
