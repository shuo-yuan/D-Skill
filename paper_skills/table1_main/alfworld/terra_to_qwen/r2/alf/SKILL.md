## Core Approach


Decompose every task into ordered phases before taking any action. Typical phases: locate, clean/prepare (if required), acquire, transport, and place/deliver. After each action, verify which phase you are in and whether the action moves you closer to completing that phase. Plan the sequence before acting to prevent wandering.


For put-tasks, if the object might already be at the target receptacle, navigate there first. Otherwise, use object-furniture associations to locate the object directly.

## Precondition Chains


- **Clean before moving to target**: When the goal mentions a state like *clean*, assume the object is not yet in that state. Immediately after acquiring the object, go to the nearest sink/basin/bathtub and use the corresponding "clean … with …" action **before** navigating to the final drop-off location. Before moving to the target receptacle, ask: "Does the object currently satisfy the required state? If not, is a cleaning action available among my admissible actions?" If cleaning is possible, do it first.

- **Search thoroughly before cleaning**: Before moving to a sink or basin to clean an object, systematically inspect every open surface (shelves, carts, basins, countertops) and every closed container (cabinets, drawers) in the current room. Do not assume the object is in a particular location; verify all visible storage until found.
- **Apply temperature/state changes before delivery**: When the goal asks for an object with a property like *cool*, *hot*, *chilled*, or *cooked*, do not search for an object that already has that property. Instead, locate the base object, then use the appropriate appliance to apply the property (e.g., `cool tomato 1 with fridge 1`). After picking up the base object, immediately scan admissible actions near relevant appliances (fridge, stove, microwave) for transformation commands and use one before moving to the target receptacle.
- **Cleaning pipeline**: For tasks that require cleaning an object, follow this exact sequence: pick up the object → go to the nearest sink/basin → clean the object → go to the target receptacle → place/move the object. Do not skip or reorder these steps.

- **Cleaning runtime check**: After picking up the object that needs cleaning, verify that your next two actions are: go to the sink (or other cleaning fixture) and clean the object with that fixture. Do not deviate to other locations or actions before completing these two steps. Only then proceed to the target receptacle.


- **Cleaning action example**: When you reach the sink/basin with the object, look for a `clean ... with ...` action in the admissible list (e.g., `clean soapbar 1 with sinkbasin 1`). Use it immediately without opening or examining the fixture. This matches the successful pattern observed in practice.

- **After cleaning, do not insert any `look`, `inventory`, or `examine` actions.** Go directly to the target receptacle (or the next sub-goal location) without any intermediate inspection.
- **Post-cleaning placement check**: After cleaning, confirm that you actually moved the object into the target receptacle (the action should be `move ... to ...`) rather than leaving it at the sink or in your hand.
## Search Strategy


- **First action: never use `look`.** For put‑tasks, go directly to the target receptacle; for other tasks, go to the first open surface or the most plausible container. The initial observation already lists every container – `look` adds nothing. Before emitting `look`, ask: "Is there a `go to` action available?" If yes, use it instead.

Always begin by navigating to the goal location/receptacle described in the task and examining it. If the required object is already there, the task may be complete immediately. Only if not present, proceed with a broader search. For put-tasks, this is the target receptacle; for other tasks, it's the destination.
 If the receptacle is a closed container (e.g., fridge, cabinet), open it immediately. This prepares the destination before you start searching for the object.

- **Object-furniture associations**: When the object is not at the goal location, use everyday object-furniture associations to pick the first search location (e.g., bed for pillow, fridge for food). Runtime check: before moving to any container or surface, ask: 'Is this the kind of furniture where I would expect to find a <target object> in a typical household?'

- **Open surfaces first.** Before opening any cabinet, drawer, or fridge, visit every open surface (countertop, table, shelf) listed in the initial room description in numerical order. After reading the initial observation, ask: "Does the description mention any countertops, tables, or surfaces?" If yes, navigate to one of them now. This rule overrides any other search priority, including target‑first or cooled‑item assumptions.
Before taking any action that goes to a closed container, ask: "Have I visited every open surface in this room?" Only proceed if yes.
- **Display objects (statues, vases, decorations) are almost always on open surfaces.** Before opening any drawer or cabinet, exhaust all tables, stands, and shelves. Runtime check: when the target is a decorative item, ask: 'Have I checked every visible surface without opening anything?' If not, go to the next unchecked surface.
- **Do not skip to fixtures before checking storage.** Never move to a fixture (toilet, bed, sink) before exhausting all visible containers and open surfaces. Build a mental list from the initial observation of every closed container and every open surface, then visit them one by one. Only after checking every plausible storage location should you examine a fixture. Inspect every open surface (countertop, table, shelf) listed in the room description before opening any cabinet, drawer, or fridge. This is especially important for small portable items. Before opening a closed container, ask: “Have I visited every open surface in this room?” Only proceed if yes.
- **Then open closed containers.** Open and inspect every closed container (drawers, cabinets, cupboards) at the current location. When the observation says “The <container> is closed” and `open <container>` is admissible, open it immediately. Do not move past a closed container without checking inside. Before leaving a location, confirm you have opened every closed container there. Visit them in numerical order (e.g., cabinet 1, cabinet 2, ...) without skipping.
- **Systematic category exhaustion.** Exhaust one receptacle type (cabinets, drawers, shelves, etc.) before switching to another. Visit and open every numbered drawer or closed container of that type. Before leaving a category, confirm you have opened every container of that type listed in admissible actions.
- **Visit same-type receptacles in order.** When searching across multiple receptacles of the same type, visit them in numerical order without skipping any. Do not jump from countertop 1 to countertop 3 or revisit earlier numbers until the full ordered list of that type is exhausted. Before each `go to` action, ask: “Is there an unvisited receptacle of this same type with a lower number than the one I am about to visit?”
- **Track inspected locations.** Maintain a mental list of already-inspected locations. Do not revisit empty locations without a concrete reason. Search in logical order (e.g., numerical order for numbered objects).
- **Prioritize likely containers.** If multiple container types are available and the object is still not found, rank containers by expected location (e.g., fridge for food, cabinet for plates) and visit the most probable one first, then continue systematically.
- **Final absence check.** Before concluding an object is not present, verify: “Have I opened every unvisited drawer or closed container across all categories?”

- **Target-first for put-tasks**: For any “put X on Y” task, you may first navigate to Y to check if X is already there; if found, the task is complete. If a strong object-furniture association (e.g., soapbar on countertop) suggests a likely location, you may go there directly to acquire X, then deliver to Y. Before moving to any other location, ask: “Have I checked the target receptacle yet, or do I have a strong association for X's location?”
- **Search protocol**: Before starting a search, list all container types in this order: open surfaces (countertops, tables, shelves), then closed containers (drawers, cabinets, cupboards), then remaining furniture/fixtures. For each type, list all numbered instances in numerical order. Commit to visiting them all without skipping. After each move, ask: 'Have I exhausted all instances of the current type? If not, proceed to the next instance immediately. If yes, move to the next type.' Only deviate from the plan if the target is clearly found.
- **Cooled items first.** If the task requires an object in a cooled state (e.g., "cool", "chilled", "frozen") or the target is a fresh/perishable food item typically stored cold (e.g., lettuce, eggs, milk, butter), make the fridge your first destination. Open it and examine contents before searching other locations. Before selecting your first action, verify: "Does the task mention a cooled state or is the item typically kept cold? If yes, am I heading to the fridge?" If not, redirect to the fridge.
- **Avoid `look` when starting a search**: The initial room observation already lists all containers. Never use `look` at the very start of the task; the initial observation already describes all visible objects and containers. If you use `look`, you'll waste a turn and may see "you see nothing". Instead, go directly to the first open surface (e.g., countertop 1) and visit every numbered instance of that type in order. After each visit, ask: “Have I visited every instance of this container type? If not, go to the next one immediately.”
- **No revisits**: Once you have inspected a receptacle, do not return to it during the same search phase unless you receive new information that an object has been placed there. Even if you know a previously visited receptacle still contains a target object (e.g., for multi-item tasks), continue searching all unvisited receptacles before returning. After each inspection, proceed directly to the next unvisited receptacle in the established order. Before each `go to`, ask: "Have I already inspected this container? If yes, skip it and go to the next unchecked one."

- **Checklist from initial observation**: Before starting a search, extract every receptacle name from the initial room description (e.g., coffeetable 1, tvstand 1, shelf 1) and create a mental checklist. Visit each one in order, marking them off as you go. Do not skip any receptacle that appears in that initial description. Runtime check: after each `go to`, if any receptacle on that checklist remains unvisited, choose one of them next.

- **Broaden search after exhausting a location's containers**: After you have opened and inspected every container associated with a single piece of furniture (e.g., a desk and its drawers), do not loop back to that piece. Instead, move to the next furniture type listed in the initial room description (e.g., shelves, sidetables). Before revisiting any location, ask: "Have I visited every other furniture type visible when I first looked around?"

- **After any failed closed-container search, check open surfaces next**: If you opened a closed container (fridge, cabinet, drawer) and did not find the target object, immediately check all open surfaces (countertops, tables, shelves) in numerical order before opening any other closed containers. Ask: "Have I already examined every visible countertop and table in the room? If not, go to one of those first."

- **Table-first for common tabletop items:** If the target object is a mug, cup, plate, book, or other item typically found on tables, visit all `diningtable`, `sidetable`, `desk`, or `coffeetable` surfaces before opening any drawers or cabinets. Runtime check: when you see both `drawer` and `diningtable` in the admissible actions, ask: “Is this object commonly found on a table? If yes, go to the table first.”

- **Confirm empty containers with `examine`**: When you arrive at a container and the observation says "you see nothing" (or similar), immediately use `examine <container>` to double-check. This ensures you don't miss items that only appear on closer inspection.

- **Immediate pickup when target is visible**: When you arrive at any surface or container and the observation lists the target object, immediately use the `take` action for that object. Do not waste steps on `look`, `examine`, or checking other items. This applies even if you are in the middle of a systematic search.


- **Name-matching surfaces first**: When searching for an object whose name matches a receptacle type (e.g., `desklamp` → desk), visit all receptacles of that matching type in numerical order before moving to other surface types. Runtime check: after checking all name-matching surfaces, if the object is still not found, proceed to the next surface type in the go-to list.
- **Parse observations for object locations**: Upon entering any room, scan the observation for every object mentioned, noting which container or surface it sits on. Match task keywords (e.g., "desklamp", "pillow") to these objects and plan your next move based on where they are located.
- **Multi‑item tasks:** When the task requires multiple objects of the same type (e.g., two creditcards), after placing one object, resume the systematic search from the next unvisited container in the order you were following. Do not jump to a different furniture type or guess. Keep a mental note of the last inspected container and proceed to the next one in numerical/logical sequence.
- **Persistence after first location failure**: When the required object is not found at the first associated location (e.g., desklamp not on desk), do not give up or try a substitute. Instead, use the object's name to infer other plausible locations (e.g., shelf, table, bed for a desklamp) and systematically check them in order. Before concluding the object is absent, verify: "Have I visited all candidate locations implied by the object's name and the initial room layout?" This ensures you exhaust reasonable places before abandoning the task.

- **After checking the fridge for a cooled item and not finding it, do not return to the fridge later.** Mark it as inspected and proceed to search open surfaces and other containers systematically, following the open-surfaces-first rule.
- **Hot‑spot first move**: Before moving to your first search location, quickly list the top one or two most likely surfaces for the target object based on everyday associations (e.g., stoveburner for pots, countertop for food). Go to one of them. This avoids aimless wandering. Runtime check: before the first move, ask "What are the top 1-2 surfaces where this object is commonly found?" and choose one.
## Action Validity & Recovery


- **Open closed containers immediately**: If you arrive at a container that is "closed" and `open` is an admissible action, use that action right away. Do not move to another location or check inventory before opening it. Runtime check: "Is this container closed? If yes, open it now." **Exception for appliances**: If the closed container is an appliance (e.g., microwave, fridge, stove) and the admissible actions include a composite action like `heat X with Y`, `cool X with Y`, or `cook X with Y` that uses the appliance, do not open it manually. Instead, use the composite action directly. This prevents unnecessary manual steps. For non-appliance containers, always open and inspect before leaving, even if you plan to clean or transform the object.
- Avoid `look` or `inventory` unless you are lost and have no clear next action. After completing a sub-goal (e.g., cleaning, heating, cooling), the next step is known; navigate directly without inspecting. If the last observation is still current, skip these actions and proceed to the next useful step. Before issuing `look`, ask: “Do I already know the next location? If yes, go there now.”
- **Placement tasks**: When you need to put an object onto a receptacle, always use the `move <object> to <receptacle>` action from the admissible list. Do not attempt "put", "place", or other commands not present. Before acting, verify that the exact `move ... to ...` action is in the admissible list. For example, if the admissible list shows `move cup 2 to coffeemachine 1`, use that exact command; do not type `put cup 2 in coffeemachine 1`.

- **Composite appliance actions**: When the task requires heating, cooling, or cooking an object with an appliance, always look for a composite admissible action like `heat X with Y` or `cook X with Y` and use it directly. Do not manually open/close the appliance unless the composite action is absent. Before opening an appliance, scan the admissible action list for a `heat … with …` (or `cook … with …`, `chill … with …`) action that includes the appliance name.
- **Open closed target receptacles before placing**: If the observation states that the target receptacle is closed, you must open it before using `move` or `put`. Do not attempt to place an object into a closed container. After opening, then use the `move` action. If the receptacle is already open and `move` is admissible, you may use it directly without opening. Runtime check: "Is the target receptacle closed? If yes, open it now; otherwise, if `move` is admissible, use it directly."

- **Strict admissible action selection**: Before emitting any action, confirm that the exact action string (including all arguments) appears verbatim in the current admissible actions list. If it is not listed, choose a different admissible action or adjust your plan. Never type an action that is not currently offered.

- **Concrete example**: When at an appliance (e.g., microwave) holding the target object (e.g., tomato) and the admissible list contains a composite action like `heat tomato 2 with microwave 1`, use it immediately. This avoids unnecessary open/close steps and was proven effective in practice.

When searching for objects, never use `inventory` before opening a closed container you are standing at; open it first.

- **Runtime check for semantic actions**: When standing at an appliance with the object, scan the admissible list for a semantic transformation verb (`cool`, `heat`, `cook`, `clean`, `chill`, etc.) that matches the task requirement. If such an action is present, use it immediately without manually opening/closing or moving the object into the appliance. This is more reliable than decomposing into `open`/`move`/`close` steps.

- **Remote pickup**: When you need to acquire an object, before moving to any location, scan the list of admissible actions for a `take [object] from [surface]` entry that matches the target object (including plausible synonyms like `pan` for `pot`). If found, execute that action immediately; it will pick up the object without you having to navigate to that surface. Runtime check: "Is there a take-action in the list that would give me the target object right now? If yes, use it."
## Task-Type Procedures


- **Put-tasks**: After picking up an object, before moving to the target receptacle, verify whether the goal requires any state transformation (clean, cool, heat, slice, etc.). If yes, perform that transformation immediately (go to the appropriate fixture/appliance and execute the transformation action). Only then go to the target receptacle and use `move <item> to <receptacle>`. Resume searching only after placing it. Runtime check: after every `take`, ask: "Does the goal require a state change? If yes, have I performed it? If not, go to the fixture/appliance now. If no transformation is needed, can I move the item to the target receptacle right now?" Follow accordingly.

- **Put-tasks (search)**: Before searching for the object, identify the target receptacle type from the goal (e.g., countertop, cabinet, fridge). Then exhaust all instances of that type in the current room before moving to other container types. For example, if the goal is 'put a bread in countertop', visit countertop 1, countertop 2, etc., in numerical order, checking each for the object. Only after all of that type are exhausted, move to other types like cabinets or drawers. This aligns with the systematic category exhaustion rule.
- **- **Complete transformations before final placement**: Before moving to the target receptacle, verify that all required transformations (heat, chill, clean, etc.) have been applied to the object. Right before executing the final `move` action, confirm that all verbs from the task instruction (e.g., "heat") have been performed. If not, perform them first.

Upon arrival at the target receptacle**: Immediately execute the `move <object> to <receptacle>` action; do not look, inventory, or examine first. Confirm the move action is in the admissible list and select it right away.
- **Post‑pickup sequence**: After picking up the target object (and after any required transformation), your next two actions must be: go to the target receptacle, then move the object to it. Do not insert any other actions between these two steps. Concrete check: after an observation that confirms “You pick up…”, verify that your next two actions are “go to [target]” and “move [object] to [target]”.
- **Cool-and-place tasks**: Follow this three-phase template: (1) obtain the exact named object, (2) take it to a cooling appliance (fridge) and apply the `cool` action, (3) take it to the target receptacle and apply `move` or `put`. Before acting, state the three phases to yourself and confirm the current step belongs to one of them.
  - Before applying the `cool` action, ensure the fridge is open; if it is closed, open it first.

- **Examine/Use tasks**: When the task requires examining or using a specific object, navigate to its expected surface and pick it up before attempting any examine or use action. Runtime check: before any examine/use, verify the object is in your inventory; if not, go to its container and take it.

- **Keep object in inventory when using a tool**: After picking up the object, go directly to the tool (lamp, microwave, etc.) and use the tool while holding the object. Do not place the object on a surface first. Before using the tool, confirm the object is in your inventory; if yes, use the tool immediately.

- **Instrument-based examine/use tasks**: When the task uses a phrasing like “examine X with Y” or “use X with Y”, first acquire X, then navigate to Y, and only then interact with Y (e.g., `use Y`). Never use `examine` on X alone before reaching Y. Runtime check: before any `examine` action on the target object, ask: “Does the goal mention an additional tool or location that I have not yet reached or picked up?” If yes, skip the `examine` and move toward that tool/location.
 If you have already picked up X and `examine X` appears in the admissible actions, do not select it. Instead, navigate to Y and use Y. The tool interaction (e.g., `use desklamp`) is the final action that fulfills the examination.

- **Lamp-based examine tasks**: When the task says 'look at X under Y' and Y is a lamp (e.g., desklamp), after picking up X, use Y (the lamp) to turn on its light. This is the reliable final step.
When you arrive at a location where X is visible and a `take` action is admissible, take X immediately without examining the surface or the lamp.


- **Landmark-first tasks (acquire object before moving to landmark)**: When the task mentions a tool or landmark (e.g., "with Y", "under Y", "using Y"), do NOT navigate to Y first. Instead, first go to the location where X is typically found (use object-furniture associations), take X, and only then go to Y. Runtime check: before moving to Y, ask "Have I acquired X? If not, go to X's typical location first."
- **Exception for co-located object and tool**: If both the target object and the tool (e.g., desklamp) are small items that are likely to be on the same surface (desk, table, shelf), and the initial room description identifies a single furniture item that can host both, navigate to that furniture first. Once there, pick up the target object and then use the tool. This avoids separate trips. Runtime check: in the first observation, scan for a single furniture item that plausibly holds both the object and the fixture, and `go to` it before any other action.
## Common Pitfalls


- **Perform required transformations before final placement**: If the goal includes a state modifier (clean, cooked, chilled, cool, hot, etc.), apply that transformation immediately after picking up the object, before moving to the target receptacle. Immediately after `take`, scan the goal for state words; if present, navigate to the appropriate appliance (fridge, microwave, sink) and apply the transformation action. Do not place the object first. This applies even if the object was found on a surface; the object is not yet in the required state.
- **Stop after final placement**: After executing the action that places the object at the goal location with the required state, stop. Do not follow with `look`, `examine`, pick-back, or extra navigation actions. Verify: "Did I just accomplish the exact goal? If yes, and there is no error message, I should stop."
- **Never use `look`; minimize `inventory`**: The initial observation already lists all containers, and moving to a location reveals its contents. Never use `look`. If you need a fresh room overview, instead `go to` a known surface. Use `inventory` only if you just picked up an object and cannot recall what you are carrying. Before emitting `inventory`, scan the last observation: if it already states your inventory contents, do not repeat that action. When standing at a container, never use `look`. If the container is closed, open it; if open, use `examine` to see its contents. Before using `look`, ask: "Have I already seen this container's full contents? If yes, skip `look` and proceed to the next action." Runtime check: before any `inventory` or `look`, ask "Does the last observation already tell me my inventory and the room contents?" If yes, skip it.
- **Do not re‑examine a container after taking an object**: After a successful `take`, the previous observation already shows the container's remaining contents. Do not `examine` the same container. Proceed directly to the next subgoal (place the object, clean it, etc.). Runtime check: after `take`, if admissible actions include `examine` on the same container, skip it and select an action that moves you toward placing or processing the held item.- **Do not pick up unrelated objects**: When the task is to find and deliver a specific object, only interact with that exact object. Do not pick up, clean, or move any other items you encounter during the search. Before picking up an object, verify: 'Is this the exact object I need? If not, leave it alone.' If the object name does not appear verbatim in the task description, do not pick it up.

- **Do not settle for a similar object**: If the task asks for a specific object (e.g., pencil), do not accept a similar object (e.g., pen) until you have exhaustively checked every visible surface and container from the initial room overview. Before placing a substitute, verify you have visited every receptacle listed in the starting observation.

- **Premature task completion**: Before concluding the task is done, verify that you have physically found and, if required, used every object named in the task description. If the instruction mentions multiple objects (e.g., "examine the bowl with the desklamp"), you must locate and interact with all of them. Do not treat a noun as merely descriptive unless the task explicitly says so. Runtime check: after any action that you think completes the task, list the objects you have handled; if any object from the instruction is still unseen or unused, continue searching.

- **Take required objects as soon as you see them on a surface**: When you arrive at a surface (countertop, table, etc.) and spot an object you need, use `take` immediately. Do not leave to search other locations first, especially if multiple required objects are co-located. Runtime check: After arriving at a surface, scan admissible actions for `take <needed-object>`; if present, execute it before moving elsewhere.

- **Do not examine after pickup**: After you pick up the object required for the task, do not `examine`, `look`, or `inventory`. Instead, go directly to the target receptacle and use `move`. Runtime check: after every `take`, if the object is needed for placement, ask "Am I holding the object? Yes → Go to the target receptacle now."


- **Take target objects immediately; never examine first**: When you arrive at a surface or container and the observation lists the exact object you need, use `take` right away. Do not waste a turn on `look`, `examine`, or any other action before picking it up. This applies even if you plan to use the object later at a different location (e.g., examine with a tool). Carrying the object while searching for the secondary item is efficient and prevents losing it.
- **Move on if the target is absent**: After arriving at a location and reading the observation, if the target object is not listed, do not stay and use `look` or `examine`. The observation already tells you what is there. Immediately `go to` the next unvisited location in your search plan. Repeated `look`/`examine` at the same spot wastes turns and delays progress.
- **Break movement loops by switching action types**: If you notice yourself revisiting the same two or three locations without progress, stop moving and take a different category of action — such as taking an available object, using an interactable item, or checking your inventory. Track the last three locations; if the sequence looks like A → B → A → B → A, halt movement and try an action that is not "go to" (e.g., take, use, examine an object).
- **Do not apply transformations unless required**: If the task does not explicitly ask for a state change (e.g., cool, clean, heat), do not use those actions. Instead, use the direct placement action (`move ... to ...`). Before using a transformation action, confirm the task instruction contains that verb.
- **Do not delay placing a picked-up object**: After a `take` that acquires an object needed for a put-task, immediately scan the admissible actions for a `move … to [destination]` action. If it is present, execute it now—do not explore other locations or take extra steps before placing the item. Resume the search only after the object has been moved.

- **After any `go to` action, if the observation already describes what is on the receptacle (e.g., 'On the countertop, you see ...'), do not use `look`.** The contents are already visible; proceed directly to the relevant interaction (take, examine). Runtime check: After any `go to`, read the observation; if it lists items, skip `look` and choose an action that uses the listed items.
- **Never use `look` at the start of a task** — the initial observation already provides a complete list of cabinets, surfaces, and appliances. Using `look` replaces that detailed description with a vague summary (often "You see nothing."), making navigation impossible. Before any `look`, ask: "Does the last observation already list all the room’s cabinets, surfaces, and appliances?" If yes, skip `look` and use the existing list to navigate.
- **Skipping open surfaces for drawer-typical items**: Even if the target object is commonly stored in drawers (e.g., spoons, forks, knives), always inspect all open surfaces (countertops, tables, shelves) first. The open‑surfaces rule overrides any object‑furniture association. Before going to any drawer, ask: 'Have I visited every open surface in this room?' If not, go to the next unvisited open surface.
- **After picking up an object, if the next destination is known (e.g., fridge for cooling, sink for cleaning), go there immediately; do not use `look`.**
- **Do not re‑apply the same transformation**: After a successful `heat`, `cool`, `clean`, etc., the object is in the required state. Do not retrieve it and apply the same transformation again. Move directly to the next subgoal. Before taking an object from an appliance and issuing a new transformation action, check recent observations: if the object was already described as being inside the appliance after a successful transformation, skip the retrieval and re‑transformation.
- **Avoid unnecessary appliance open/close after transformation**: After a composite transformation action (e.g., `heat X with microwave`), do not manually close or open the appliance. The action already handled the appliance state. Proceed directly to the next subgoal (e.g., `take X from appliance`, `move X to ...`, or navigate away).
