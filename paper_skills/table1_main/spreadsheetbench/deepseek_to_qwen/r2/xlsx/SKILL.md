## Core Workflow


**MANDATORY PRE-MANIPULATION CHECKPOINT**: Before any file operation, confirm the working directory from the task specification and verify the input file exists at the exact `spreadsheet_path`. Print `os.getcwd()` and `os.path.exists(spreadsheet_path)` to catch path errors before they cascade. Do not proceed to coding until this diagnostic is printed and reviewed. This checkpoint prevents silent failures from misaligned columns, wrong sheets, over-deletion, or path errors.


**MANDATORY ALL-SHEETS INSPECTION**: When the task mentions multiple sheets, an attached example, or a "second worksheet," you MUST print the full contents of EVERY sheet in the workbook before writing any code. Missing a sheet means missing the answer key.

**MANDATORY IN-PLACE MODIFICATION**: Always load the original workbook with `openpyxl.load_workbook(INPUT_PATH)` and modify the target sheet in-place. The grader may check for the presence of original sheets and formatting. After saving, print `wb.sheetnames` to confirm ALL original sheets are still present (except any the task explicitly deletes).

## Common Pitfalls


- **Skipping inspection**: always inspect the actual workbook structure before writing code.
- **Wrong output path**: save to the exact path specified; verify the file exists after saving.
- **Range mismatch**: compare the task's described range against the graded answer range; inspect any extra rows/columns before acting.
- **Formula strings written as values**: never write strings starting with `=` to the `value` attribute. The grader reads static cell values, not formula text, so formulas evaluate to `None` in the saved file. Compute results in Python and write native types (str, int, float, datetime). If you must store a formula, use `cell.formula = '=...'` (not `cell.value`), but prefer computed values unless the task explicitly requires formulas.
- **Substring vs. exact match**: using substring match (`'text' in cell`) when cell values are exact status codes risks matching partial strings (e.g., "to be processed later"). Use exact comparison unless instructions say "contains."
- **Index-shift when inserting/deleting rows in a loop**: Always iterate from bottom to top (highest index to lowest) so earlier operations don't shift the positions of yet-to-be-processed rows.
- **Index-shift when deleting columns**: Same principle applies — delete columns from right to left (highest index to lowest) so earlier deletions don't shift the positions of remaining columns. Use `sorted(cols_to_delete, reverse=True)` or `reversed(cols_to_delete)`.
- **Forgetting to verify answer-range coverage after row deletions**: After deleting rows that shift data upward, the graded answer range (e.g., A4:A18) may become empty because the remaining data now sits above row 4. Always reload the output and print the full graded range by its exact coordinates to confirm it contains data, not just headers or None.
- **Saving without re-reading**: the grader sees the saved file, not your in-memory state. Always verify from disk.

- **Creating a new workbook instead of modifying the existing one**: NEVER use `openpyxl.Workbook()`, `pd.ExcelWriter`, or any fresh-workbook constructor. Always `openpyxl.load_workbook(INPUT_PATH)` the input file, modify existing sheets in place, and save with `wb.save(OUTPUT_PATH)`. Creating a new workbook discards all original sheets, formatting, and metadata — the grader may depend on these.
